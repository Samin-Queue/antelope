# evals — 임계값이 조용히 바뀌는 것을 막는다

이 저장소에는 실측으로 고른 상수가 여럿 있다. 0.50(항목명 유사도),
0.6(근거 매칭), 0.5(병합 신뢰 하한), 6자(짧은 needle 게이트). 전부 「올리면
못 찾고 내리면 엉뚱한 값을 채운다」 자리인데, **바꿨을 때 무엇이 나빠지는지
확인할 방법이 없었다.**

## 무엇을 검사하나

**순수 함수만.** LLM 을 부르지 않으므로 키·비용·시간이 들지 않고, 결과가
결정론적이다. 임계값 회귀는 대부분 여기서 잡힌다.

| 대상                         | 지키는 것                                   |
| ---------------------------- | ------------------------------------------- |
| `normalizeKey` · `makeNeed`  | 같은 항목을 두 번 묻지 않는다               |
| `documentKey` · `mergeNeeds` | 빈 키가 와일드카드가 되지 않는다            |
| `matchEvidence`              | 근거를 못 찾으면 **빈 배열**이다            |
| `verify` 규칙                | 형식은 맞고 내용이 틀린 값을 잡는다         |
| `contractOf`                 | 스키마에서 파생한 계약이 필드를 안 빠뜨린다 |
| `pruneToolResults`           | 최근 창만 남기고 원본을 안 건드린다         |

## 돌리는 법

```bash
pnpm eval
```

**CI 에는 붙이지 않는다.** 3명이 같은 방에 있는 팀에서 게이트를 늘리는 것이
순손실이라는 저장소 판단(AGENTS.md 「CI / PR 리뷰」)과 같은 이유다. 임계값이나
프롬프트를 만질 때 손으로 돌린다.

## LLM 케이스는 아직 없다

녹화·재생이 있어야 결정론적으로 돌릴 수 있다. `src/lib/ai/meter.ts` 의 `fetch`
훅이 그 자리다 — 거기서 요청·응답을 파일로 떨구게 확장하면 fixture 가 생긴다.
그 전에 골든셋을 만들면 매번 값이 달라져 아무것도 못 지킨다.
